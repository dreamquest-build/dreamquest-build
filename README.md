# DREAM QUEST BUILD

株式会社ドリームクエスト（大阪府堺市）の建設事業サイト初期版です。本番公開・ドメイン接続は行っていません。

## 起動する

Node.js 22以上を用意し、このフォルダーで以下を実行します。外部パッケージのインストールは不要です。

```sh
npm run dev
```

ブラウザーで `http://localhost:3000` を開いてください。クラウド環境では、使用しているツールのポート3000のプレビュー機能をご利用ください。停止は Ctrl+C。別のポートを使う場合は `PORT=3001 npm run dev` で起動します。

更新後は `npm run build` を実行し、ブラウザーを再読み込みしてください。起動済みのサーバーはそのまま使えます。`npm test` でページ・リンク・画像参照・基本SEO設定を検証できます。

## ファイルの役割

- `src/content.json`：会社情報、施工実績、お知らせ、採用情報。更新担当者が編集するデータです。
- `public/images/`：写真を置く場所。
- `public/styles.css`：デザインとスマートフォン表示。
- `public/app.js`：メニュー、施工実績の絞り込み、問い合わせ内容確認。
- `scripts/build.mjs`：データから17ページを生成する仕組み。
- `dist/`：生成されたサイト。ここを直接編集すると次のビルドで上書きされます。

JSONの編集では、文字列を半角の二重引用符で囲み、項目の間に半角カンマを入れます。最後の項目の後にカンマは付けません。編集前にコピーを保存しておくと安心です。エラーが出た場合は最後の変更箇所の引用符・カンマをご確認ください。

## 施工実績を追加する

1. `src/content.json` をテキストエディターで開きます。
2. `projects` 内にある既存の1件をコピーし、配列の末尾に追加します。
3. `slug` に重複しない半角英小文字・数字・ハイフンの識別名を入れます。これが詳細ページのURLになります。
4. 次の各項目を実際の情報に変更します。

```json
{
  "slug": "warehouse-renovation-01",
  "name": "工事名を入力",
  "category": "工場・倉庫",
  "location": "掲載可能な所在地を入力",
  "scope": "施工内容を入力",
  "completed": "竣工時期を入力",
  "sample": false,
  "photos": [
    {"src": "/images/warehouse-01.webp", "alt": "倉庫の改修後の外観", "caption": "完成写真"},
    {"src": "/images/warehouse-02.webp", "alt": "倉庫内部の施工中の様子", "caption": "施工中"}
  ]
}
```

カテゴリーは `公共工事`、`工場・倉庫`、`店舗`、`事務所`、`改修工事`、`外構`、`その他` のいずれかを使います。`sample: true` は掲載イメージであることを表示する設定です。実績として確認できた案件だけ `false` にしてください。情報が不明な項目は `PLACEHOLDER：確認後入力` を残してください。

5. `npm run build` を実行すると一覧・詳細ページが生成されます。テストは施工実績の件数に合わせてページ数を自動確認します。

## 写真を差し替える

1. 掲載許諾を確認した写真を `public/images/` にコピーします。ファイル名は半角英数字・ハイフンを推奨します。
2. 対象実績の `photos` に上記のように画像を登録します。1枚目が一覧のサムネイルになります。完成・施工中の写真を何枚でも追加できます。
3. `alt` は写真に何が写っているかを短く説明します。`caption` は任意のキャプションです。
4. `npm run build` を実行します。画像は横幅1600〜2000px程度、WebPやJPEGで1枚500KB程度以下を推奨します。

`photos: []` のままなら建築物のデザイン入りプレースホルダーが表示されます。TOPの施工実績は同じ写真を自動で使います。TOPの大きな建築イラスト・会社紹介イラストを実写真にする場合は `scripts/build.mjs` 内の対象 `art(...)` を `<img>` に置き換える作業が必要です。写真が無くても初期版は動作します。

## 会社情報を変更する

`src/content.json` の `company` 内を編集します。会社名、所在地、代表者、電話番号、建設業許可、宅地建物取引業免許、堺市・大阪府の入札参加資格を登録できます。代表者名は会社概要にだけ表示されます。許可・資格は番号と区分を確認してから入力してください。

会社名・ブランド・拠点表記を変更する場合は共通ヘッダー／フッターや本文にもあるため、`scripts/build.mjs` の該当文字列も確認してください。架空の番号・連絡先は登録しないでください。

## お知らせを追加する

`news` の先頭に次の形式で追加します。配列の順番でTOPに表示されます。

```json
{"date": "2026-10-02", "title": "お知らせのタイトル", "body": "お知らせの本文"}
```

日付は実際の発表日に変更してください。既存の「準備中」告知は正式運用時に削除できます。追加後 `npm run build` を実行します。

## 採用情報を更新する

`recruit` 内の職種・雇用形態・給与・勤務時間・休日・福利厚生・勤務地を変更し、`npm run build` を実行します。未確定の待遇を推測で入力しないでください。

## 問い合わせと公開前の確認

現在のフォームは必須入力の検証→確認画面→修正まで動きます。メール送信やサーバー保存は行いません。送信完了と誤認しないよう画面に明示しています。フォーム入力をURLやローカルストレージに保存する仕組みもありません。

本番公開前には次の準備が必要です。

- 正式な連絡先・許可番号・資格・募集要項・施工実績と掲載許諾済みの写真。
- 問い合わせ送信先と送信方式の決定、バックエンド実装、迷惑送信対策、実際の送信テスト。
- 個人情報取扱方針の確定（`/privacy/` は現在PLACEHOLDER）。
- プレビュー用 `noindex,nofollow` と `robots.txt` のアクセス抑制設定を正式公開時に見直す。
- canonical・OGP・sitemapには予定ドメインを設定済み。実際の公開先を確認する。
- OGPはSVGのデザイン案です。SNS向けには1200×630pxのPNG/JPEGに書き出し、OGP参照を変更する。

本サイトは静的HTMLなので任意の静的ホスティングに対応できますが、今回は本番公開も独自ドメイン接続も行っていません。フォントはGoogle Fontsを補助利用し、取得できない場合は端末の日本語フォントで表示されます。ブラウザー管理画面やCMSはまだありません。

## GitHub Pagesでブラウザー確認する

プレビュー用ソースは `site-preview` ブランチ、公開ファイルは `gh-pages` ブランチです。独自ドメインは設定しません。

GitHubのリポジトリで **Settings → Pages → Build and deployment** を開き、Sourceを **Deploy from a branch**、Branchを **gh-pages**、フォルダーを **/(root)** にして **Save** を押します。数分後、Pages画面に表示されたURLから開けます。GitHub側の公開権限・プランによってはPagesの利用設定が必要です。

想定URL：`https://dreamquest-build.github.io/dreamquest-build/`（公開前は404です）。GitHub Pagesは一般にURLを知る人が閲覧できるプレビューです。独自ドメインによる正式公開とは別です。

再生成するときは `BASE_PATH=/dreamquest-build npm run build` を使います。ローカル用は `npm run build`。生成ファイルを `gh-pages` に更新するとプレビューに反映されます。
